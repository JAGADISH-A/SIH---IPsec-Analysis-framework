## 1. Executive Summary

The project is **not** "everything implemented." It is a system where the **sensor, evidence, state, feature,
windowing, comparison, risk, and XAI layers are genuinely built and exercised against real testbed traffic**, while
the **ML-to-correlation bridge, the observed-state construction path, and the entire streaming layer are real code
that is never invoked by any production entry point.**

The single most important finding: **the deployed dashboard does not display live pipeline data.** It runs *real*
engines over *synthetic* inputs — the default plan is a file under `tests/fixtures/`, the "observed" state is
generated by a formula, and the `MLResult` is hand-constructed rather than produced by the trained Random Forest.

Three findings require action:

| # | Finding | Severity |
|---|---------|----------|
| 1 | **BROKEN:** `controller/ipsec_events.py:143` raises `NameError` on any IKE packet lacking `isakmp.length` — a live-path crash in the audit CLI's only production path. | Critical |
| 2 | `correlation/api/store.py:41` default `PLAN_PATH` resolves into `tests/fixtures/`; `store.py:257` synthesizes observed state; `store.py:272` hand-builds `MLResult`. The dashboard presents fixture-derived data as if live. | High |
| 3 | `correlation/ml/controller_bridge.py` (the only module connecting the trained RF to the correlation layer) and `correlation/streaming/pipeline.py` (the only module constructing `ObservedStateBuilder`) have **zero non-test importers**. | High |

**Passive architecture is intact and was independently verified.** The XDP program returns `XDP_PASS` on both exit
paths, contains no `XDP_DROP`/`XDP_TX`/`XDP_REDIRECT`, and is fed by `tc mirred` *copies* into a separate sensor
namespace — it is non-inline and cannot enforce.

**Anomaly detection: DEFERRED — no anomaly implementation is required in this milestone.** This is not a gap and
is not counted as one below. Only an inert data seam exists.

## 8. Security / Authority-Boundary Verification

**A. ML authority — PASS.** `RiskEngine.assess` takes `ml_result` as an *optional evidence input*; `risk/policy.py`
`ml_handling` caps ML-derived severity at informational and `scoring.py` documents "the anomaly score is never
converted" into risk. `comparison/ml_comparison.py:57` forces `is_authoritative_observation=False`. Tests assert the
cap (`test_risk_engine.py:200,212,440`). ML never produces a security decision.

**B. Expected-state independence — PASS.** `correlation/adapters/expected_state.py:9-10` states it "never compares
expected against observed… never runs any ML." `from_plan` (`:326`) reads plan/config only. No ML import in the
expected-state path.

**C. SHAP non-interference — PASS.** Grepping `correlation/` for `shap` yields 6 incidental matches (the word "shape"
in docstrings). No SHAP output is consumed by comparison, risk, policy, or response. `controller/test_ml_inference.py::TestShapNonInterferenceAndContract::test_explain_is_observational` enforces it. `correlation/xai/` explains an already-computed `RiskAssessment` and never alters score, severity, or findings.

**D. Risk semantics — PASS.** Deterministic. Inputs: `expected`, optional `observed`, required `correlation`, optional
`ml_result` (evidence only), optional `evidence_refs`. Weights INFO0/LOW6/MED12/HIGH25/CRIT40, per-category cap 30,
global cap 100, dedup before scoring, fixed bands, validated invariant that the lowest band is `INFO == 0`.
Called from `correlation/api/store.py:276` and `correlation/tools/execute_phase6.py:105`.

**E. Audit provenance — PARTIAL.** Only **observation** stages persist: `controller/ipsec_events.py:288-347` and
