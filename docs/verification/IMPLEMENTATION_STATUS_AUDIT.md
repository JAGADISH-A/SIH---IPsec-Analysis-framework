# Implementation Status Audit — IPsec Analysis Project

**Type:** audit + minimal remediation. Findings 1–6 were fixed with the smallest change that makes the
claim true, each with new regression tests; no architecture was replaced and no pre-existing test was
modified. Everything else is classified, not implemented.
**Date:** 2026-09-25
**Branch:** `feature/security-assessment` @ `6e051e0`
**Method:** repository inspection, forward import-reachability analysis, artifact inspection, live test
execution, and execution of the real pipeline on committed artifacts.

## 1. Executive Summary

The project is **not** "everything implemented." It is a system where the **sensor, evidence, state, feature,
windowing, comparison, risk, and XAI layers are genuinely built and exercised against real testbed traffic**, while
the **ML-to-correlation bridge, the observed-state construction path, and the entire streaming layer are real code
that is never invoked by any production entry point.**

The single most important finding: **the deployed dashboard does not display live pipeline data.** It runs *real*
engines over *synthetic* inputs — the default plan is a file under `tests/fixtures/`, the "observed" state is
generated by a formula, and the `MLResult` is hand-constructed rather than produced by the trained Random Forest.

Six findings were actionable; all six are now closed, and the remaining items are classified in §11:

| # | Finding | Severity |
|---|---------|----------|
| 1 | **RESOLVED** — was: `controller/ipsec_events.py:143` raised `NameError` on any IKE packet lacking `isakmp.length`, a live-path crash in the audit CLI's only production path. Reproduced against the pre-fix source and fixed; see §13.3. | Closed |

| 3 | **RESOLVED** — was: `correlation/ml/controller_bridge.py` and `correlation/streaming/pipeline.py` reported **zero non-test importers**. True of the streaming layer (it is an intentionally non-production alternate architecture) and **false for the bridge**: the production RF path is the `python -m correlation.ml.live_correlation` stage, which calls the bridge once per live window. The audit counted imports and never ran the stage. See §13.4. | Closed |
| 4 | **FIXED (real defect)** — was: `PcapRegistry.register()` had no production caller, so every `/api/v1/evidence/*` request 404'd while risk assessments carried dangling `evidence_refs`; the dashboard also passed `sequence=0`, which `EvidenceRef` rejects behind a broad `except`. The real path now registers, downloads and verifies actual PCAP bytes. See §13.5. | Closed |

| 6 | **FIXED (real defect)** — was: a live ML result named only `model_version`, so it could not be tied to one model file even though `train_report.json` already recorded the artifact digest. Every result now carries the digest of the artifact that produced it. See §13.6. | Closed |

Everything still open is classified in **§11**, which also records what is deliberately *not* a
defect: the nearest-centroid-only `model_metadata` contract, the lab PSK literal, the unwired Zeek live

**Passive architecture is intact and was independently verified.** The XDP program returns `XDP_PASS` on both exit
paths, contains no `XDP_DROP`/`XDP_TX`/`XDP_REDIRECT`, and is fed by `tc mirred` *copies* into a separate sensor
namespace — it is non-inline and cannot enforce.

**Anomaly detection: DEFERRED — no anomaly implementation is required in this milestone.** This is not a gap and
is not counted as one below. Only an inert data seam exists.

### 3.3 The seam is an entry point, not an import

The arrow from 3.1 into 3.2 exists. It is drawn by the **stage**
`correlation/ml/live_correlation.py`, which is executed, not imported:

    python -m correlation.ml.live_correlation --events <xdp|tshark>.jsonl \
        --plan results/datasets/<run>/staging/plan.json --sequence 1 \
        [--model results/ml/model_traffic_rf_v1.joblib] --output result.json

`controller_bridge.py` is on that path (the stage calls `infer_controller_ml_result`
once per live window). Because the stage is a `__main__`, a static importer scan
necessarily reports **no in-process importer for it** — which is why this audit
originally recorded the seam as missing. Reachability had to be proven by running
the stage, not by counting imports. Verified in §13.4.

`correlation/streaming/pipeline.py` is a **superseded alternate architecture** and
is deliberately not wired into this path; see §13.4 for why wiring it would add a
second, Random-Forest-blind ML path.

## 4. Implemented vs Integrated Distinction

**IMPLEMENTED + INTEGRATED (real production callers):**
`ExpectedStateAdapter` · `ComparisonEngine` · `RiskEngine` · `ExplainabilityEngine` · `comparison/clock.py` ·
`controller/audit.py` (JSONL) · `correlation/api/*` server · RF classifier in `controller/` ·
`ml/controller_bridge.py` (via the `live_correlation` stage) · `ebpf/ipsec_state_builder.py` (via the same
stage and via `correlation/api/store.py`) · `correlation/config.py` (settings only)

**IMPLEMENTED, NOT INTEGRATED (no production caller):**
`correlation/response/**` (all 9 modules) · `correlation/execution/**` (all 8 modules) ·
`correlation/streaming/**` (all 14 modules incl. `pipeline.py`, `ml_provider.py`, `live_adapter.py`, `windowing.py`) ·
`correlation/schemas/`

**`correlation/streaming/**` is an intentionally non-production alternate architecture, not a pending gap.**
It is the earlier Phase 10 in-memory event-stream layer. It is left unwired on
purpose: its ML provider cannot accept the committed Random Forest, its only
window builder is a labelled test double, and its `ObservedStateBuilder`
duplicates — with documentation-range endpoint defaults — the authoritative
`ebpf/ipsec_state_builder.py`. Wiring it would create a second, weaker ML path
(§13.4). `correlation/config.py` consumes only `streaming.config.StreamingConfig`
(settings), never the pipeline.

**Note on `correlation/api/store.py`:** it is production-integrated but *data-synthetic*. The engines are real; the
inputs are fixtures and formulas. This is the most consequential distinction in the audit.

**Definitive test-only module list** (`correlation/`, verified by forward reachability from all 44 entry points
cross-checked with symbol grep):
`config` · `schemas[.json_schema]` · `streaming.{pipeline, consumer, producer,
live_adapter, ml_provider, models, schema, windowing, backpressure, dedup, dead_letter, retry, offsets, partitioning,
topics, config}` · `response.{engine, approval, authorization, audit, planner, policy, rules, executor, models}` ·
`execution[.base|.executors|.gates|.host|.idempotency|.targets|.settings]`

`ml.controller_bridge` was removed from this list: it is reached in production by the
`live_correlation` stage and, for recorded model output, by `correlation/artifacts.py`
(§13.2). Reachability was re-verified by execution, not by import counting.

The `__init__.py` aggregator packages (`correlation.streaming`, `.response`, `.execution`, `.schemas`, `.config`,
`.tools`) have no importer outside tests, which is why their re-exported submodules appear "imported" yet remain
unreachable.

### 13.3 Finding #1 — the IKE live-path `NameError`

**Reproduced** against the pre-fix source (`909410d^`) with the smallest possible input — one `isakmp` frame with no
`isakmp.length`:

```
PRE-FIX  IKE packet WITHOUT isakmp.length  -> NameError: name 'ip' is not defined
PRE-FIX  IKE packet WITH    isakmp.length  -> packet_length = 292   (the `or` short-circuits; bug hidden)
```

**Root cause.** `normalize_ike_event` unpacked `_outer_addrs(layers)` as `(src, dst, _proto)` — the `ip` dict stays
bound inside `_outer_addrs` and never leaks. Line 153 then read `_as_int(ip.get("ip.len"))` on the *right* of an
`or`, so the undefined name was only evaluated when `isakmp.length` was absent **or falsy**. `_as_int` returns
`0` for a declared length of `0` and `None` for an unparsable value, so a malformed header took the branch too. The
exception escaped `parse_tshark_json` → `observe_live`, aborting the whole observation run and losing every ESP
record in the same batch.

**Why it was latent.** Every fixture *and* every recorded input carried the field: all 16 `isakmp` frames in
`results/e2e-verification/transport/{v6_parser_tap,icmp_parser_tap,ipv6-parser-rerun/*}.json` and all 8
`ipsec_ike_observation` records in `results/audit/events.jsonl` have a real `packet_length`. The fallback branch was
never taken by any committed input.

**Reachability, measured rather than assumed.** With the host's TShark 4.6.4 and the production filter
`esp or isakmp`: a frame truncated before the length field is *not* dissected as `isakmp` (so it is filtered out
before the parser), and a header declaring `isakmp.length` of `0` or `1` is likewise rejected by the dissector. IKEv1
(`version 0x10`) is dissected and *does* expose `isakmp.length`. So this TShark build does not currently feed the
parser a length-less `isakmp` frame — the crash was reachable, but only from a producer that omits the field
(a different TShark build, a JSON artifact re-parsed by
`results/e2e-verification/transport/ipv6-parser-rerun/bridge_parser_to_state.py`, or a preference change). The code
was wrong regardless: it read a name from an inner scope on a live path.

**Minimal fix** (already in the tree at `909410d`, unchanged since): the length is read by a helper instead of by a
name from an enclosing call.

```python
def _ip_total_length(layers):
    return _as_int(layers.get("ip", {}).get("ip.len"))
...
"packet_length": _as_int(isakmp.get("isakmp.length")) or _ip_total_length(layers),
```

**Behaviour chosen: record the incomplete observation, do not skip and do not raise.**

- *Not a skip.* The packet is a real IKE exchange; its exchange type, message id, ports, endpoints and direction are
  all present and remain reportable. Dropping it would lose real observations.
- *Not a structured parse error.* One malformed frame must not abort a run that has already collected other packets.
- *Not a fabricated length.* The fallback uses only `ip.len`, a field the packet itself carries; when nothing
  supports a length, `packet_length` is `None` and is persisted as JSON `null`. No length is ever derived from
  `frame.len`, UDP length, or the expected configuration.
- A packet with no `isakmp.exchangetype` is still dropped by the existing `parse_tshark_json` guard, and a
  parser-level problem is never turned into a protocol conclusion.

**Regression coverage** — `controller/test_ipsec_events.py`, **25 passed**:

4. **It has no production transport.** `streaming/producer.py` ships only `MemoryTransport`; the
